# Clique、凝聚子图与图枚举：结合 BCviz 的未来研究展望

调研日期：2026-10-16。依据为 [文献与算法调研](reference-enumeration.md)、用户上传的 BCviz 正式全文，以及其中列出的正文方法证据。以下均为拟议研究，不代表已实现、已证明新颖性或已获得实验提升。侧重数据库算法与系统，兼顾可视分析；不以“加一个 LLM”作为默认创新。

## 1. 优先做什么

按你更看好的并行算法方向，优先阅读 [并行论文对照表](reference-enumeration.md#parallel)。研究首选 **固定内存预算下的并行二部图枚举：减少可迁移搜索状态和闭包/邻域计算成本**。已有多核、GPU 和分布式研究，因此研究重点须超出简单多线程与负载均衡，详见首要方向 P。

第二选择是 **面向重复阈值与种子查询的、容量受限的精确枚举索引**：让不同查询共享安全候选证书与部分搜索工作，支持取消、继续和结果分页，同时明确没有结果时的完成判定。它最接近 BCviz 的“离线紧凑索引 + 在线图削减”，也能形成可测的查询负载价值。

第三选择是 **动态二部图上的精确差分枚举与可见性协议**：维护新增、消失和失去极大性的结果，避免旧排序/旧证书误剪，利用有边界的 delta 与重建机制控制内存。这个方向更难，而且 change-sensitive clique/biclique maintenance 已有成熟方法，不能把“只枚举变化”当作新贡献。

另一条算法方向是 **从 biclique 推广到大 maximal k-biplex 的模型特定安全索引**。该方向图算法味更浓，需重建局部界和候选覆盖证明；仅把 biclique 搜索换成 biplex 搜索不足以形成论文。

| 方向 | BCviz 可继承内容 | 必须形成的新增成果 | 难度 | 投稿定位判断 |
|---|---|---|---|---|
| **P. 内存受控的并行枚举（优先）** | 候选削减、二部图结构与局部上界 | 新共享闭包/状态表示、正确切分、总工作与内存控制 | 中高至高 | CPU 原型优先，GPU/分布式后续；需超出已有 stealing |
| A. 重复查询与共享证书的精确枚举 | 结构顺序、阈值区间、安全上界、附加索引 | 跨查询支配规则、容量/摊销分析、可核验完整性 | 中高 | 优先考虑 VLDB/SIGMOD，依赖强工作负载与新算子 |
| B. 更新下的差分枚举 | 小型基底索引、保守候选界 | 更新安全性、消失/新增判定、维护与重建策略 | 高 | 有潜力，但邻域动态枚举已有强竞争 |
| C. 面向大 k-biplex 的候选索引 | 二部图表示、剥离与削减经验 | 不依赖完全二部连通的界、跨参数安全性 | 高 | 适合算法型 VLDB/SIGMOD/ICDE；理论证明负担较大 |
| D. 因子化结果与按需展开 | 紧凑表示、共享结构 | 精确编码语义、谓词下展开/去重、空间界 | 中高 | 需区别已有 clique aggregation 与 counting-only 压缩 |
| E. 交互式凝聚结构探索 | 曲线、区间、原图联动 | 有 ground truth 的分析任务与用户研究 | 中等 | VIS/TVCG 或数据库 demo；完整数据库研究仍需核心算法 |

## 2. 哪些问题不能混在一起

**maximal（极大）**是无法再严格扩张的可行对象；**maximum（最大）**是大小或权重最优。大量极大对象可能远小于最大对象。固定大小 clique listing、所有 maximal cliques、top-k 最优团、clique counting 是四种不同任务，复杂度与实验输出单位各异。

全解枚举设结果族为 R，显式输出顶点 ID 的总长度 `L=Σ[r∈R]|r|`。至少需要 Ω(L) 的写出工作；极大团数量本身可指数级。应研究减少无效搜索和共享重复劳动，不能宣称任意图上“线性时间输出所有结果”。压缩输出换了输出表示，展开仍需付出 Ω(L)。

延迟不只包括相邻两个结果之间，也要计入首个结果前和最后一个结果至声明完成的时间。阈值下“没有结果”也可能需要昂贵搜索。若要求按 clique 大小降序、一般图多项式预处理且多项式首结果延迟，第一个结果就能求 maximum clique，除非 P=NP，不能有这样的普遍保证。可停止的 DFS 与真正有最坏延迟界的算法不同。

全局极大性还必须指定查询域。允许顶点集合 A 下的 `G[A]` 中极大，可能并非原图 G 中极大。size 下界筛选、seed containment 和任意属性过滤的语义也不相同；缓存 key 必须记录图快照、模型/参数、允许域、极大性域和规范输出顺序。

对 γ-quasi-clique，还要区别全局边密度与逐顶点最低度定义。按逐顶点 `deg_S(v)≥γ(|S|−1)` 定义，一般不具有遗传性；“没有单顶点可加”不等于 inclusion-maximal。例如 γ=0.6 的四环是可行的，从一条边加任意第三个顶点都得到不可行的三点路径，但四点全集可行。因此 clique 的简单扩展与停止证明不能直接移植。

## 3. BCviz 正文给出的机会与限制

BCviz 的正式信息和详细条目见 [文献调研](reference-enumeration.md#i08)。两个数组的 Θ(|U|+|V|) 是额外索引空间，查询仍需要原图。BCviz+ 使用边凝聚度上界保持最大 biclique 查询精确性；BCviz− 省略部分更新，不能为全部枚举结果提供同样确定性召回保证。

**原文 §7(5) 已经明确提出**：在 MEB 索引上，对约束 `|S|≥s, |T|≥t` 选 `θ=st` 的 peak intervals，在候选诱导子图中调用现有 maximal biclique 枚举器。因而“BCviz + iMBEA/ooMBEA”应当成为最基本的继承基线，而不是直接写成未来论文首要创新。

原文 §7 还指出边插入/删除可能导致整个连通分量重排。上界计算的局部线性与总构建线性不同；索引构建复杂度、原图/缓存/结果空间都应单列。已有最大查询实验没有测枚举的首结果延迟、尾延迟、全解去重和输出落盘。

可继承的资产是 C++ 图结构、core 剥离、排序、阈值候选削减和可视曲线。需要重新建立的是枚举语义、跨查询复用、完整性证书、内存控制、动态维护及对应实验。

### 3.1 不能绕过的近邻工作与新颖性门槛

| 计划主张 | 已有近邻 | 新研究必须超出的部分 |
|---|---|---|
| BCviz 区间加 MBE 内核 | BCviz §7(5) | 跨查询新证书/新界，而非组合本身 |
| 小型索引回答双阈值/局部查询 | αβ-core 索引、MBCI personalized maximum biclique | 全体极大结果、二维过滤精度、总空间和负载摊销 |
| 多查询共享图枚举 | [Batch HC-s-t Paths](reference-enumeration.md#f05) | 全局极大性、在线容量限制与阈值支配证书 |
| 不保存全部旧结果的动态枚举 | [Incremental MCE](reference-enumeration.md#d01) | 新索引依赖维护与重复查询成本；不能只换数据结构名字 |
| 时序低延迟与持久化 | [2026 link-stream 输出敏感算法](reference-enumeration.md#d09) | 具体时间/空间折中，不能泛称首次 polynomial delay |
| 小空间保存全部团结构 | clique aggregation、[Kaleido](reference-enumeration.md#g13)、[geometric biclique cover](reference-enumeration.md#f04) | 精确解族语义、过滤后的唯一展开；容器/cover 不等于全解 |

尚未取得全文的 MBCI、部分 mixed-update/并行论文仍需补读后才能形成投稿级的新颖性结论；其元数据明确存在，不应忽略。

## 4. 首要方向 P：固定内存下的并行二部图枚举，减少搜索状态与闭包计算

### 4.1 为什么这比“直接多线程化”更值得研究

已有 ParMCE/ParTTT 解除分支依赖、GPU MCE 使用工作捐赠和部分邻域编码，cuMBE 等 GPU biclique 工作也已有两级负载均衡。下一步不能只提出外层 OpenMP、work stealing 或 degree-based 分区。

更具体的切口是：**共享/增量表示规范 biclique 搜索状态，让任务切分、迁移和闭包检查少复制、少做重复邻域访问，并在固定 RAM/显存下仍能正确列出全解。** BCviz+ 可以提供候选区域入口，但是否优于廉价 core/度排序，需要消融；它不是已证明必需的组件。

cuMBE 的方法与性能分解提示，在一些已测试大图中，两级 stealing 后空闲已很低，更细粒度均衡未必抵偿同步成本；另一些图主要耗时来自子树获取时的状态复制或 maximality 检查。这支持先 profiling 再定义新算子，不能从“搜索树不均衡”直接推断“新调度器一定有大收益”。

### 4.2 三条具体路线与优先顺序

| 路线 | 算法对象与拟创新点 | 最接近的已有能力 | 难度与建议 |
|---|---|---|---|
| P1. 多核 CPU 的共享闭包状态与可拆分任务 | 不复制整块局部图；共享不可变邻接/交集，增量保存闭包与 sibling 排除；明确唯一所有权 | ParMCE、共享内存 MBE、强单线程 MBE 内核 | 首选。原型中等；证明、降低实际内存流量较难 |
| P2. CPU/GPU 的容量感知任务与数据布局 | 按任务所需字节而非只看顶点数选择展开位置；减少 Pg/候选子图复制，保持精确展开 | GPU MCE、cuMBE/bitmap MBE | 高。需 GPU，先验证瓶颈确实在复制/访存 |
| P3. 分布式长尾任务与有界状态迁移 | 大任务细分、邻接/闭包复用、通信与输出背压；研究新成本/工作边界 | MapReduce MBE、G-thinker 等 | 更高。通信与复现负担重，不建议第一篇同时做 |

P1 不应只是 P2 的弱化版。可以研究二部图特有的闭包/双侧候选共享规则，给出在切分后仍保留全局极大性的可迁移任务状态。其算法贡献比“对每个区间起线程”更清楚，但是否新颖仍要与具体 MBE 原文/实现逐项比较。

### 4.3 一个可实现的 P1 原型

固定同一图快照、同一规模阈值和规范顺序。首先比较三种根划分：原强 MBE 的排序/根、core 削减后的根、BCviz+ 候选区域再按 canonical root 划分。每个结果只属于一个根；区间/局部图枚举不能省略全图极大性条件。

任务状态显式包含左右已选/闭包、候选、排除集合、分支位置及共享图/快照引用。考虑以共享不可变 CSR/bitmap 基底与小 delta 表示状态，必要时局部物化，避免每次 split 深复制完整局部图。闭包与候选交集共享必须有确定键和生命周期管理，碰撞后核验真实键。

共享某个 closure 并不表示 P/Q、分支所有权或完成状态相同；closure 计算结果可复用的条件和整项搜索可复用的条件需分开。

只在存在空闲 worker 且剩余工作足以摊销迁移时切任务；这部分沿用已有 stealing 作为工程底座。新研究应聚焦状态表示和共享闭包/交集如何减少总工作与峰值字节，而不是把阈值调优包装成新并行算法。

[EDBT 2025 large k-plex](reference-enumeration.md#r03) 已按任务组共享 seed graph 并在超时后拆分，[Quick+](reference-enumeration.md#r05) 已做 big-first 与 timeout-based decomposition；“共享一个根图 + 超时拆任务”也不能单独作为创新。区别应落实到二部闭包状态的可证明共享/迁移规则和减少的实际工作。

规模、候选度、|P|/|X|、相交密度可以作优先级估计，**不等于剩余真实工作量的准确上界**。估计错了只应影响调度效率，不得因此剪掉可行分支。优先级与正确性剪枝分别实现。

### 4.4 必须成立的性质与成本模型

- **全解一致性**：任意切分/迁移/取消恢复后，每个全局 maximal biclique 恰由一项 canonical 任务产生；不以概率 hash 去重替代证明。
- **状态一致性**：共享父状态不可被一个 worker 的剥离/闭包修改污染；copy-on-write 或版本化增量必须明确恢复与引用释放顺序。
- **工作开销可审计**：分开计内核有效搜索、交集重算、状态编码/复制、排队、同步与输出。争取用切分次数和实际复制字节量界定新增工作，不能没有依据地宣称整个并行版与最佳串行版同阶。
- **内存控制**：所有活跃状态、共享缓存、待发送任务和未消费输出都计入预算 M；每个 worker 的最小状态、输入图和分配器元数据也要单独计量，不能声称任意小 M 都可运行。达到上限时局部深搜/背压，而非继续复制到 OOM；但内存上限可能使并行度降低，应报告该折中。

设并行实际工作为 W、关键路径 D、线程数 p，理想工作–深度模型提示 `T_p` 受 W/p 与 D 制约；若需显式输出 L 个字节，还受输出带宽约束。模型中的调度界不代表实际必有 p 倍加速，内存带宽、NUMA 与数据传输都可能主导。

BCviz 构建也要计量：其排序依赖先前顶点，原文已说明难以并行。可并行计算部分独立局部上界，不等于整个构建没有串行部分。已有索引的一次查询与包含构建的完整工作流应分开；若靠 Q 次查询摊销，报告 break-even Q。

### 4.5 如何证明值得做，而不是只多用了硬件

在相同图、约束、结果集合与输出方式下，分别比较：最佳可复现串行算法、同内核串行版、已有并行算法、新并行版。这样既能量化并行效率，也能避免以弱串行内核做分母。

核心实验是 1/2/4/8/… 线程的强扩展曲线、同一内存预算下的吞吐/首解/尾部、总工作放大、每次切分复制字节、maximality 检查次数、共享命中、NUMA/带宽与输出堵塞。若论文只 count，另开一致的 count 模式；完整输出模式写出相同格式和相同目的地。

消融：相同 stealing 换状态表示、相同状态换根划分、去掉 BCviz、共享交集开/关、强制复制与增量恢复比较、关闭/开启输出背压。若收益来自廉价 bitmap 或 CSR 布局，要明确归因，不能归给凝聚索引。

前两周先用现成多核 CPU 和两三个有不同瓶颈的二部图 profiling。若原有并行方法已经均衡，且状态复制/重复闭包只占很小比例，应停止新调度/共享方案，转向真正占比高的内核计算；若输出带宽主导，也不要再宣称搜索树分割能解决该负载。

P1 的可运行实现通常可由熟悉 C++/图算法的研究者推进；形成有竞争力的论文仍需新共享/切分规则、正确性、成本边界和强基线。P2/P3 资源与调试难度更高，建议在 P1 证据成立之后选择一条扩展。仅“BCviz + 多线程 + work stealing”目前不足以支撑顶会贡献主张。

### 4.6 更具体的算法备选 P0：安全阈值层次的并行构建

这一方案比“重新调度搜索树”更偏图算法，但仍是**需要新颖性和性能验证的提案**。给静态二部图每条边设置上界 `w(e)≥σ(e)`，σ(e) 为包含该边的最大 edge-biclique 面积；若上界只针对索引构建时的最低规模，则查询也须满足对应最低规模条件。可用廉价 `d(u)d(v)` 起步，或用 BCviz+ 更紧的安全界；令 `G_θ=(V,{e:w(e)≥θ})`。

对于规模约束 s,t，取 θ=st。在以上前提下有简单的安全性论证：

1. 任意目标 biclique B 的每条边都满足 `w(e)≥σ(e)≥|L_B||R_B|≥st`，所以 B 完整落在 G_θ 的某个连通分量内。
2. 若分量诱导原图内一个满足规模的 biclique 能在全图扩张，扩张后的 B′ 面积仍≥st，新点连接它的边也全部权值≥st，新点便在同一分量，矛盾。因此在**原始图的分量诱导子图**内做正确 maximal 枚举即可保持全局极大性。这里不是不检查就输出任意局部闭包。
3. 固定加权图的 maximum spanning forest 保留每个阈值的连通分量。可并行求森林，再建 Kruskal 合并树，二叉森林至多 2n−1 个结点，表示所有阈值划分；相等权需统一采用 `≥θ`，不能在同权合并中切出错误分区。

这些是标准 threshold-connectivity/MSF 性质与保守上界条件的组合，**不是新的 MSF 定理**。BCviz 按“与已排序集合的最大边权”维护优先队列，也具有 maximum-Prim 风格；单纯换成现成并行森林，仍不足以支撑新颖性。可引用 [并行 MSF 实现基础](reference-enumeration.md#p08)，但不能把其 O(m log n) 工作界当整个构图/枚举的界。

潜在新增机制是：预算受限地收紧少量昂贵边上界，控制局部中心图计算与重复邻域访问，再用更细组件生成低复制并行任务。未计算的边必须保持偏大的安全界；度数乘积在 hubs 上可能把全图连成一块，届时没有削减收益。只收紧一条树边并不保证组件真的分裂，其它未收紧非树边可能重新连接；必须重算/正确维护森林，不能只删树边。

持久合并层次 O(n) 不等于整个构建 O(n) 空间：临时边权 O(m)、排序、并查集、中心图、任务与输出都要计量。BCviz− one-spot 本来省略了部分计算；全边预计算再并行可能增加总工作。先完成固定安全权的正确基线，再判断 lazy refinement 是否值得，避免第一版同时实现复杂动态 MSF。

本次做了有限的独立正确性检查：180 张 3×3、4×3、4×4 随机二部图、2,220 组 s/t 查询，核对最大生成森林与阈值原图的分区，以及分量内枚举和全图约束 maximal biclique 集合相同。代码与结果在 `/workspace/research-notes/enumeration/check-threshold-components.py`、`threshold-component-check.json`；使用度数乘积上界。它不替代一般证明，也没有测性能或表明此提案优于现有方法。

## 5. 方向 A：重复查询负载下的精确枚举索引

### 5.1 具体任务

在固定二部图快照 G 上，查询为 `q=(s,t,Q_U,Q_V)`：输出包含指定左右 seed、且两侧规模至少 s/t 的所有全局 maximal bicliques，去重且允许流式读取。先固定全图极大性和无额外属性过滤，降低证明负担；任意过滤留作扩展。

实际负载来自可视探索中阈值连续调整、seed 小范围切换和分析会话。需要公开负载生成规则，并加入随机阈值、冷查询及低复用负载。不能只选择高度重复且收益最大的查询序列。

种子若在两侧之间本身缺边，可立即返回空；包含种子的任何扩展必须保留相应的公共邻居，但局部削减后仍需检查原图中的极大性。

静态图、固定极大性定义下，仅改变规模下界，答案确实可以从全体 maximal bicliques 中过滤；问题是全体结果可能大到无法物化。目标是在明确缓存容量 M 下共享搜索工作，优于“每次重新运行”和“全量结果缓存”，而不是另建无限大结果索引。

### 5.2 拟议结构

基底使用 BCviz+ 或其它安全候选索引；在上面维护分层证书而非所有完整结果：

- 某搜索状态的 canonical prefix、候选/排除集合或可重建摘要，及所在图快照。
- 由状态导出的左右规模上界、seed 可达条件和已证明不可能区域。
- 已展开子树的完成标记；未完成 frontier 的恢复位置。
- 有限的局部输出块与跨查询命中统计，达到 M 时按明确策略驱逐。

不同 θ 下 peak intervals 可能合并/分裂，不能只用相同区间编号或 root ID 判断可复用；应核对真实候选域、chosen/candidate/excluded、规范顺序和版本。

这个设计只是研究起点。普通 DFS 保存栈、LRU 缓存和结果分页都是现有工程技术；新贡献必须在“哪些查询可以安全支配/复用哪些搜索证书，怎样避免重新证明全局极大性，何时值得保留”上。

### 5.3 一个更具体的算法探针：二维规模包络

BCviz 的 θ=s·t 将两侧规模形状压成标量；相同面积的很不平衡结构，对高 s/低 t 与低 s/高 t 的查询可能产生不同无效候选。可研究在少量区间/规范状态保存保守二维规模上包络，以便判定目标 `(s,t)` 不可能达到。它必须胜过 α/β-core 已有的双侧必要条件，而非只把 core 阈值换一种写法。

不能为任意图承诺精确二维 Pareto 前沿仍为 O(n)，也不能将已经找到的若干 biclique 当作所有可行规模的上包络；未探索区域仍可能有更优形状。先用容量受限、允许变松的保守包络，记录构建、查询节省和退化，比较标量 peak、局部 core 与二维界的增量价值。该机制尚待设计和证明。

### 5.4 应先证明的安全命题

与已有多查询工作的直接比较也必须补齐：ICDE 2024《Batch Hop-Constrained s-t Simple Path Query Processing in Large Graphs》已用查询支配、公共子路径物化、query-sharing graph 和引用计数释放共享图枚举工作。因此不能泛称首次“多查询共享图枚举”；本提案需具体区别全局极大性、二维阈值证书、在线容量约束及其安全复用。

**阈值支配**：在同一状态能证明所有完成解都满足 `|L|≤u_L, |R|≤u_R` 时，若 `u_L<s` 或 `u_R<t` 可整支剪掉。证书必须是真的上界，不能来自 BCviz− 的欠估；状态规模上界也不能由其已找到结果的最大值代替。

**跨查询复用**：若状态已在更宽松阈值 `s0≤s, t0≤t` 下完整枚举，则同域、同图快照下它对更严格阈值的剩余搜索可省略；但是若完整输出没有缓存，仍需重建/重扫以实际返回符合结果，不能只凭“已完成”声称可免费回答。应把不可能证书、已完成证书和可重放输出分别处理。

**seed 变化**：新增 seed 可以筛去不包含它的已缓存结果，但对尚未展开状态，需要安全判定 seed 是否仍可能加入。去掉 seed 是放宽查询，原先 seed 搜索没有覆盖的其它状态不能因此标成完成。

**分页与取消**：完整页不能跨快照混合；canonical owner 保证输出不重不漏；共享状态键还必须保留 candidate/excluded 与分支所有权，不能仅按已选顶点缓存。hash 只能加速定位，碰撞后应核对真实键。取消只保存已实际完成的状态，正在展开但未提交的块应可重放/去重，不能直接升级为完成。磁盘 checkpoint 的大小与恢复开销都要计量。

这些命题并不自动带来总体速度优势。界过松、缓存易被驱逐或本来输出就主导时间时，收益可能接近零。

### 5.5 算法与分析目标

优先将 `peak interval → canonical root → 搜索子树` 分层：首次查询惰性展开，保守界先过滤，必要时调用强 MBE 内核；下一次查询在相同根和查询可兼容证书上复用。每条结果包含唯一 canonical key；区间覆盖与 root 分派需整体证明，不能只用最终 hash 去重掩盖重复搜索。

可争取的理论是：相对于从零运行的同一内核，分开界定基底构建、证书验证、缓存命中重放和新增状态展开成本。任何摊销结论都应包含查询数、总输出长度、缓存容量/驱逐和重建次数；不预先承诺一般图的 poly-delay 或常数更新。

一个合适的失败边界是：当重复负载仍不优于标准局部图缓存或 degree/core 索引 + 强内核，应停止把 BCviz 排序当作必需组件，重新检查结构局部性是否真带来价值。

## 6. 方向 B：动态二部图的差分枚举与证书失效

### 6.1 目标与已有方法的区别

对更新批次 ΔE，输出 `R_new\R_old` 与 `R_old\R_new`。变化不仅是新增/删除边所属的结果，还包括原结果被更大结果吸收、从而失去极大性。例如原图边为 u1–v1、u1–v2、u2–v1，{u1}×{v1,v2} 原本极大；加 u2–v2 后它被 2×2 biclique 包含，虽然旧结果本身不含新边。一个插边可令原先并不包含该新边的旧 biclique 不再极大；不能仅删除含变化边的结果记录。

动态 maximal clique/biclique 的 change-sensitive 方法已经存在；部分方法并不要求保存全部旧结果。拟做的价值应集中在**重复阈值查询索引及跨版本共享证书的维护**，并与直接动态枚举、全量重跑比较。

### 6.2 可能方案

保留不可变基底和 delta 图。旧 BCviz 排列只作物理布局；正确性依赖当前图的精确邻接、可见性及重新建立的安全界。若仍用旧 peak intervals 承担保留全解的责任，必须证明覆盖没有失效，或让受影响部分退回完整安全候选域。

索引条目记录版本和依赖区域；更新后可能欠估的界应立即上调为保守值或禁用剪枝。对固定 chosen/candidate 域中所有可行完成对象推导、且已证明对删边单调的结构上界，删除后偏大的旧值可以暂时保留，只影响效率。若界只覆盖旧的 global-maximal 结果或旧 canonical ownership，则不具备这个自动安全性；maximality/完成状态也必须失效，因为删除可产生原来不极大的新结果。

单条更新可能影响大量结果，输出敏感性要显式进入成本。单边可触发整个 core 的级联变化，巨型连通分量使“只处理局部”退化为全图。应设计退化检测与重建阈值，报告何时回退，而非保证任意更新都很快。

### 6.3 最低正确性实验

在能穷举的小图上，对随机插入、删除、批量互相抵消和跨分量连接/拆分，逐次比较完整 oracle 结果集；校验新增、消失、失去极大性以及重复结果。再扩大图规模测维护、重建、输出和查询总成本。

并发可先采用单写者批次快照：每个枚举 cursor 固定快照，更新生成下一版本，旧 cursor 结束后回收。不要一开始同时承担分布式一致性与所有松弛模型。

## 7. 方向 C：从 biclique 到 large maximal k-biplex 的安全索引

biclique 要求左右两侧完全相连；k-biplex 允许每个点对侧少量缺边。真实交互图中小量缺边可能更合理，但结果空间、候选可达范围和极大性判断都更难。不同论文 k 的定义可能差一，必须在 API 和实验中统一。

BCviz 边凝聚度和 peak 定理针对完全 biclique，不能未经证明沿用于 biplex。可以研究缺边预算下的候选分组、上界和局部恢复结构，底层必须接强 maximal k-biplex 枚举内核，比较 iTraversal/后续 pivot 和 large-size 算法。

潜在形式是按缺边预算保存可证明的候选上界，而不是为所有 k 和所有规模组合预存完整搜索树。参数表若按顶点×k×规模全铺，空间会膨胀；需明确阶梯/分段压缩是否精确、哪些参数可复用以及构建代价。

一般 k-plex 中，采用 `deg_S(v)≥|S|−k` 约定，大小至少 ℓ 的解必须包含于 `(ℓ−k)`-core（阈值非正时不给有效剪枝）；这是已有且基本的必要条件。新方法不能仅重述它。二部两侧预算和规模界要分别推导，不能直接把一般图公式逐字替换。

高阶残缺结构的局部邻域结论通常依赖解足够大，过小解可能不连通。实验需包含低规模和大 k 的反例，明确研究的是 large maximal biplex 子任务；不能先丢掉困难的小解再将算法称为全部解枚举。

## 8. 方向 D：精确因子化输出与按需展开

当大量结果共享顶点、前缀或交换模块，可以尝试返回紧凑结果族，并支持 contains-vertex、规模过滤、计数和惰性展开。但必须指定编码精确表示哪些 maximal 对象、不同分支是否重叠，以及遍历时如何去重。

已有 maximal clique aggregation、闭模式/闭项集、ODAG、subgraph decomposition、ranked query enumeration 都与此有关。2026 年《Aggregating Maximal Cliques in Real-World Graphs》返回覆盖全部极大团的密集容器，容器可包含非边，因此不是全部团家族的精确可展开表示。LMCS 2025 的 ranked CQ 与 PVLDB 2022 的 projection 排名枚举已经分析预处理、延迟和去重；但 fixed-query 定理也不能直接当作未知大小 maximal clique 的通用延迟界。counting 使用 inclusion–exclusion、乘积聚合或过近似 DAG 时，并不一定能直接输出每个合法 embedding；有的方法在显式写出模式时必须退回原始枚举。

因此可以比较三种输出契约：只返回数量、精确因子化结果、展开全部 ID。前两种更快不能混写为显式全枚举更快。无损结构在最坏输入上未必显著压缩，建议给出适用图族与退化行为，避免无条件紧凑承诺。

若延伸到 GraphRAG/向量检索，MCI（2026）已经使用局部 maximal-clique cover 构造带属性过滤的近似近邻索引；几何二部图 weighted biclique cover（2026）也已有结构假设下的压缩保证。两者都不等于一般图的精确极大对象枚举，需引用并说明任务差异。

这条方向与 A 有联系，但证明和对照文献较多；若主工作仍只是用前缀树缓存结果，很可能不足以区别已有压缩索引。

## 9. 方向 E：可视化帮助定义怎样的枚举查询

沿用 BCviz 的凝聚度曲线，叠加阈值候选区间、已完成/未完成搜索区、时间/内存预算、共享结果与失效证书。用户应能知道“目前看到多少结果”和“是否已经枚举完”是两回事。

典型任务可以是寻找同时包含两个种子的候选群体、比较阈值变化导致的结构差异、定位一条更新为什么使某结果失去极大性。将任务转成可核验答案，比较曲线+列表、普通节点图以及现有探索界面，测任务准确率、耗时和遗漏率。

可视界面是 A/B 的自然展示层；如没有新的枚举机制，适合 demo 或 VIS/TVCG 方向。若研究目标是 VLDB 正文稿，应先证明算子/索引对大量查询的实际收益。

## 10. 实验：优先测什么

### 10.1 基线与数据

| 场景 | 必须覆盖的基线 | 数据要求 |
|---|---|---|
| 静态 clique | BK-pivot、degeneracy、近期 reduction/hybrid 内核 | 稀疏社交/协作、近完全图、Moon–Moser 型多结果图 |
| 静态 biclique | iMBEA、ooMBEA、BBK、近期 partition-oriented | KONECT 类二部图、BCviz 原 8 组中适合枚举者、极端不平衡两侧 |
| 重复阈值/seed | 从零强内核、core+内核、BCviz+ + 内核、结果缓存、搜索栈恢复 | 真实或公开规则生成的会话，冷/热查询并列 |
| k-biplex/松弛 | iTraversal/近期 hereditary-pivot/large-size 内核 | 统一缺边约定和规模阈值，不与 biclique 数量直接比较 |
| 动态 | change-sensitive、批处理动态算法、全量重算 | 真实更新流及反例更新；插入/删除分开 |
| 因子化输出 | clique aggregation、计数/显式输出两种执行模式 | 高共享与低共享结果族，编码与展开都测 |

实际复现能力受代码许可证、数据可得性与硬件约束；缺失基线须明示原因，不能用不同论文表格中的最高倍数替代统一测量。

### 10.2 指标与公平性

- **正确性**：结果集合一致、无重复、全局极大性、约束满足、分页联合完整、取消恢复后不漏不重；小图穷举 oracle。
- **延迟**：含预处理的首结果时间、相邻结果间延迟分布与最大值、空结果证明时间、最后结果至完成声明时间；CPU/GPU 同步后计时。
- **资源**：附加索引、原图、缓存/frontier、峰值 RAM/显存分别列出；缓存容量固定比较。
- **吞吐**：results/s 和 vertex-IDs/s 同时报告；只计数、序列化 ID、写文件分别测；不能让一个方法只累加计数而另一个方法写磁盘。
- **负载成本**：索引构建+Q 次查询+更新/重建+恢复，给出相对强基线的 break-even 查询数，包含没有摊销成功的设置。
- **结构诊断**：访问边/交集数、搜索状态数、证书复用率、界紧度、重复探索、输出共享率、负载倾斜与并行空闲率。

消融保持相同内核和输出格式，只改变 BCviz 顺序、度/退化序、候选区间、安全界、共享证书与缓存策略。否则“新索引更快”可能只是下游内核更强。

为验证单边输出爆炸，可令 Q 为 p 个三点独立部组成的完全多部图，再加不相邻且都连接 Q 的 u,v。插 u–v 前每个 Q transversal 产生两项极大团，插后只剩包含 u,v 的一项；单边触发 3·3^p 个结果成员变化。该压力构造应与真实更新流分开报告。

若实现准实时或 anytime，不要只报告前 100 个结果的平均延迟；给出完整运行与终止判定，或明确运行被预算截断、尚未获得完整性保证。所有超时、OOM 和未完成运行保留在结果表中。

## 11. 实施与止损

优先做 P1 的多核 CPU 静态二部图原型，验证状态/闭包共享；重复查询 A 作为后续可摊销场景。先限定仅规模阈值与少量 seed；暂不混入 quasi-clique、时间图和异构属性。复用 BCviz C++ 存储/削减，以统一的 callback/cursor 接口连接一个强 MBE 内核；Python 管理负载、验证和绘图。枚举核心通常以 CPU、内存和输出带宽为主，不需先训练模型或购置大显存 GPU。

| 阶段 | 建议投入（有相关代码的 2 人团队） | 可核验交付 |
|---|---|---|
| 可行性探针 | 前 2 周 | 强内核+BCviz+ 继承基线；冷/热负载；全成本分解 |
| 新索引/证书 | 第 3–6 周 | 查询支配规则、容量限制、小图正确性、恢复语义 |
| 完整负载 | 第 7–10 周 | 规模、阈值、seed、缓存扰动；对照其它顺序与简单缓存 |
| 理论与消融 | 第 11–14 周 | 摊销分析边界、反例、端到端 Pareto 曲线 |

时间属于条件性计划，不是工期保证。A 的原型中等难度，严格复用证明和强基线优势较难；B/C 通常需要额外数月。单人或缺少现成内核时应缩小范围。

前两周的止损标准是：若除输出写出外的可节省成本很小、BCviz 区间不比便宜 core/度约束有效、重复负载收益完全被普通结果/局部图缓存解释，就不要继续扩大系统。可转向明确的差分维护或松弛模型索引问题，也可能得出某类负载不值得索引化的结论。

对重复查询 A，开题研究问题是：“在固定内存和完整输出语义下，能否利用重复查询的支配关系与凝聚结构，显著减少跨查询重复搜索，并给出可核验的正确性和成本边界？”若该命题经理论和实验成立，才有向 VLDB/SIGMOD 组织论文的基础。对并行 P，优先检验“在同一内存预算和完整输出语义下，新的状态/闭包共享能否减少总工作与复制，并在强并行基线之上稳定提升扩展性”。两类贡献都不能事先承诺顶会录用。
